# Правила работы с отчетами и материалами к защите (FairVendor)

## 1. Структура и размещение отчетов
- Все материалы отчетов, скрипты их генерации и вспомогательные ассеты **ОБЯЗАТЕЛЬНО** должны находиться исключительно в папке `reports/`.
- В корневой директории проекта запрещено оставлять PDF-отчеты, скрипты `generate_report_*.py` и изображения для титульных листов.
- Корень репозитория должен оставаться чистым и содержать только исходный код проекта (Django-приложения, ООП-модели, хранилище, тесты, конфигурации `manage.py`, `.flake8`, `requirements.txt`).

## 2. Требования к официальным отчетам (ГОСТ 7.32)
- Формат: PDF, лист A4.
- Оформление: титульный лист РТУ МИРЭА с официальной эмблемой (`reports/mirea_logo.jpg`), поля (левое 30 мм, правое 15 мм, верхнее/нижнее 20 мм), шрифт Times New Roman, 100% черный текст (никаких цветных рамок или фонов).
- Нумерация: снизу по центру со страницы 2.
- Лимит объема: строго регламентированное количество страниц (например, для ПР5 — ровно 3 страницы).

## 3. Обязательная шпаргалка к защите для студента
- По итогам выполнения каждой практической работы (ПР) в папке `reports/` **ОБЯЗАТЕЛЬНО** формируется подробная шпаргалка к защите (например, `reports/ШПАРГАЛКА_К_ЗАЩИТЕ_ПРX.md`).
- Шпаргалка должна содержать:
  1. **Краткую теорию простыми словами**: суть темы практики (например, Django, HTTP, маршрутизация, MVC/MTV, ORM) без сложного академического жаргона.
  2. **Что конкретно изменено в проекте**: перечень созданных файлов, приложений, маршрутов, функций и интеграций с проектом FairVendor (Тема 433).
  3. **Пошаговый сценарий демонстрации преподавателю**: команды запуска сервера (`manage.py runserver`), список URL для демонстрации в браузере, команды запуска тестов (`pytest -v`) и линтера (`flake8 .`).
  4. **Частые вопросы преподавателя (Татьяны Викторовны) и готовые правильные ответы**.
