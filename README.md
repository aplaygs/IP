# Сервис регистрации продавцов на ярмарку (FairVendor)

Консольное объектно-ориентированное приложение для регистрации продавцов, учета ярмарочных мероприятий, проверки доступности торговых площадей, расчета сборов и управления заявками.

## Назначение
Сервис предназначен для автоматизации подачи и обработки заявок от продавцов, фермеров и ремесленников на участие в ярмарочных мероприятиях. Приложение позволяет ускорить регистрацию участников, автоматизировать проверку реквизитов, рассчитывать стоимость аренды торгового места с учетом специфики продукции и лимитов площадей, а также формировать официальное подтверждение участия.

## Целевая аудитория
- **Продавцы и ремесленники:** индивидуальные предприниматели, самозанятые мастера и фермерские хозяйства, бронирующие торговые места на ярмарке.
- **Организаторы и администраторы ярмарок:** координаторы площадки, ответственные за проверку документов, утверждение заявок, учет свободных площадей и финансовый контроль.

## Предметная область
Предметная область охватывает процессы организации сезонных, тематических и городских ярмарок: ведение реестра мероприятий, учет характеристик торговых площадок (лимит площади, базовая ставка), валидацию категорий продукции (ремесла, фермерские товары, сувениры) и управление жизненным циклом заявок на участие.

## Объектно-ориентированная архитектура (ПР3)

Архитектура системы построена на принципах объектно-ориентированного программирования (ООП): инкапсуляции, наследовании, полиморфизме и ассоциации объектов.

### 1. Модель ярмарки (`models/fairs.py` -> `Fair`)
- **Атрибуты:** `id` (int), `name` (str), `location` (str), `date` (str), `base_rate` (float), `total_space` (float).
- **Методы:**
  - `is_space_available(requested_space, occupied_space) -> bool` — проверяет, вмещает ли площадка запрашиваемый стенд с учетом уже занятой площади;
  - `get_free_space(occupied_space) -> float` — рассчитывает остаток свободной площади;
  - `to_dict() -> dict` и `from_dict(data) -> Fair` — сериализация и десериализация;
  - `__str__()` — информативное строковое представление объекта ярмарки;
  - `__getitem__()` и `__contains__()` — интерфейс обратной совместимости.

### 2. Иерархия классов продавцов (`models/vendors.py` -> `Vendor`)
Демонстрирует наследование и динамический полиморфизм тарифных ставок и строкового представления:
- **Базовый класс `Vendor`:**
  - **Атрибуты:** `id` (int), `name` (str), `inn` (str), `category` (str), `has_documents` (bool), `experience_years` (int).
  - **Методы:** `get_category_coefficient() -> float` (базовый 1.2), `to_dict()`, `from_dict()`, `__str__()`.
  - **Валидация:** строгая проверка положительного ID, непустого наименования, формата ИНН (10 или 12 цифр), наличия документов и неотрицательного стажа.
- **Специализированный подкласс `CraftVendor(Vendor)`:**
  - Переопределяет `get_category_coefficient() -> 1.0` (льготный тариф для народных художественных промыслов и ремесел);
  - Переопределяет `__str__()` с префиксом `[Ремесленник]`.
- **Специализированный подкласс `FoodVendor(Vendor)`:**
  - Переопределяет `get_category_coefficient() -> 1.3` (повышенный тариф для скоропортящихся продуктов и санитарного контроля);
  - Переопределяет `__str__()` с префиксом `[Фермер/Гастрономия]`.
- **Специализированный подкласс `SouvenirVendor(Vendor)`:**
  - Переопределяет `get_category_coefficient() -> 1.1` (сувенирная продукция);
  - Переопределяет `__str__()` с префиксом `[Сувениры]`.

### 3. Модель заявки (`models/applications.py` -> `Application`)
Связывает сущности предметной области через прямые ссылки на объекты:
- **Атрибуты:**
  - `id` (int) — уникальный номер заявки;
  - `vendor` (`Vendor`) — прямая ссылка на объект продавца (доступ: `app.vendor.name`, `app.vendor.inn`);
  - `fair` (`Fair`) — прямая ссылка на объект ярмарки (доступ: `app.fair.name`, `app.fair.total_space`);
  - `requested_space` (float) — требуемая площадь стенда;
  - `fee` (float) — рассчитанная стоимость участия;
  - `status` (str) — статус согласования и оплаты;
  - `is_cancelled` (bool) — флаг аннулирования бронирования.
- **Методы:**
  - `calculate_fee(is_first_time=False) -> float` — расчет арендного сбора на основе базовой ставки ярмарки `fair.base_rate`, площади и полиморфного коэффициента продавца `vendor.get_category_coefficient()`, с учетом 15% скидки новичка;
  - `cancel()` — инкапсулированный отзыв заявки, освобождающий забронированную площадь;
  - `generate_card() -> str` — генерация официальной карточки регистрации участника;
  - `to_dict() -> dict` и `from_dict(data, vendor, fair) -> Application` — сериализация связей через идентификаторы `vendor_id` и `fair_id`.

## Возможности системы
- Загрузка и сохранение объектов предметной области в JSON-хранилище (`storage.py`) с использованием контекстных менеджеров `with open` и обработкой исключений (`FileNotFoundError`, `json.JSONDecodeError`);
- Регистрация участников с автоматическим выбором конкретного подкласса (`CraftVendor`, `FoodVendor`, `SouvenirVendor`);
- Поиск продавцов по подстроке наименования (регистронезависимый);
- Поэлементная фильтрация продавцов по товарным категориям на базе генератора (`yield`);
- Сортировка участников по имени или торговому стажу с использованием анонимных `lambda`-функций;
- Контроль лимита торговых площадей ярмарки перед оформлением бронирования;
- Формирование официальной карточки регистрации участника;
- Отзыв и отмена поданных заявок с автоматическим пересчетом свободного места;
- Сводная аналитика и статистика по каждой ярмарочной площадке (заполняемость, выручка, число утвержденных стендов);
- Полное интерактивное меню CLI и автономный демонстрационный сценарий (`--demo`).

## Структура проекта
- `models/` — пакет классов предметной области (ООП):
  - `models/__init__.py` — экспорт основных классов `Fair`, `Vendor`, `CraftVendor`, `FoodVendor`, `SouvenirVendor`, `Application`;
  - `models/fairs.py` — класс `Fair` и операции над ярмарками;
  - `models/vendors.py` — иерархия классов продавцов, валидация ИНН, генераторы и сортировка;
  - `models/applications.py` — класс `Application`, расчет сборов, карточки, проверка доступности площадей и аналитика;
- `main.py` — точка запуска приложения с интерактивным текстовым меню и автоматическим демонстрационным режимом (`--demo`);
- `fairs.py`, `vendors.py`, `applications.py` — модули обратной совместимости верхнего уровня;
- `storage.py` — персистентное хранилище JSON с автоматическим связыванием объектов;
- `utils.py` — вспомогательные функции безопасного ввода и форматирования денежных величин;
- `data/` — каталог с JSON-файлами данных (`fairs.json`, `vendors.json`, `applications.json`);
- `tests/` — каталог модульных тестов `pytest`:
  - `tests/test_fairs.py` — тесты объектной модели ярмарок;
  - `tests/test_vendors.py` — тесты классов продавцов, наследования и полиморфизма;
  - `tests/test_applications.py` — тесты модели заявок, ассоциаций объектов и аналитики;
- `test_main.py` — тесты функций начального уровня и обратной совместимости;
- `generate_report_pr3.py` — скрипт генерации официального отчета по ГОСТ 7.32 в формате PDF;
- `requirements.txt` — зависимости проекта (`pytest`, `flake8`, `reportlab`, `pymupdf`);
- `.flake8` — конфигурация линтера (100% соответствие PEP 8).
